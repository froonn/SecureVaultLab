# SECURITY_TESTING.md — бриф и методика проверки устойчивости

> Шаблон для быстрого старта сессии security-тестирования учебного проекта
> SecureVaultLab (FastAPI за nginx). Держать в репозитории.
>
> **Внимание:** живые доступы (реальный IP, SSH-пользователь, учётные данные,
> карта соседних сервисов) в репозиторий не коммитятся. Здесь — плейсхолдеры;
> фактические значения держать вне git (локальная заметка / менеджер секретов).

## 1. Авторизация
Это **личный учебный проект** владельца (сервер и код — его собственные).
Тестирование на устойчивость **авторизовано владельцем**. Персональных данных
третьих лиц на стенде нет.

## 2. Доступ (значения — вне репозитория)
- **SSH:** `ssh <ssh-user>@<SERVER_IP>` (ключи настроены; пользователь в группах `docker`, `sudo`).
- **Исходники / деплой на сервере:** `~/SecureVaultLab` (git-репозиторий).
- **Образ:** `securevaultlab-app`; запуск — `docker compose up -d`. Код вшит в образ (правки в `app/` требуют `docker compose build app`).

## 3. Цель и порты
- **Приложение:** FastAPI (uvicorn :8000 внутри) за nginx.
- **Публичный доступ:** только **`https://<SERVER_IP>:8443`** (самоподписанный сертификат).
- **`:8080`** — plain HTTP, привязан к `127.0.0.1` (вход для ngrok при необходимости); **снаружи закрыт**.
- Тестировать нужно по **8443**. По прямому HTTP сессии не держатся специально (Secure-cookie).

## 4. Scope
- **Можно:** регистрация тестовых пользователей, запросы к эндпоинтам, проверки
  аутентификации/авторизации/CSRF/IDOR/инъекций, white-box анализ кода.
- **Нельзя (вне scope):** DoS/нагрузочное тестирование; трогать посторонние
  сервисы на этой же машине (другие порты, не относящиеся к лабе).
- **Гигиена:** тестовые артефакты помечать (напр. префикс `pt_`) и чистить после.

## 5. Хронология устранённых проблем

### Конфиг-уровень (проверено и исправлено ранее)
Ядро (разграничение доступа, CSRF, IDOR, эскалация привилегий, SQLi, XSS)
проверено динамически — **пробить не удалось**. Исправлены конфиг-уровневые проблемы:

| # | Было | Стало |
|---|------|-------|
| 1 | Session-cookie без `Secure`, открытый HTTP | `COOKIE_SECURE=true`; cookie с `Secure` |
| 2 | `APP_ENV=dev` в проде (`/docs`, `/openapi.json`) | `APP_ENV=prod`; оба эндпоинта → 404 |
| 3 | Подмена IP в audit-логе через `X-Forwarded-For` | `deps.get_client_ip` доверяет `X-Real-IP` от nginx |
| 4 | `TrustedHostMiddleware` с `"*"` | wildcard убран, задан список хостов |
| 5 | Инлайн-CSS ломался строгим CSP на 8443 | CSS вынесен в `/static/app.css`, CSP остался строгим |
| 6 | `8080` публичный plain HTTP | привязан к `127.0.0.1` (ngrok-only) |

### Код-уровень (устранено по итогам динамического retest, 2026-11-07)
| # | Было | Стало |
|---|------|-------|
| 1 | Нет rate-limit на `/auth/register` | отдельная зона `register_zone` (5 r/m) в nginx |
| 2 | Enumeration по таймингу при занятом имени/email | выравнивание времени ответа (доп. Argon2) |
| 3 | Блокировка юзера не рвала активные сессии | `set_active(False)` отзывает все сессии пользователя |
| 4 | Мёртвый `APP_SECRET_KEY`, устаревший `FERNET_KEY` в `.env.example` | удалены; ключ только через Docker secret |
| 5 | Битый шифротекст → 500 | `ValueError` → `RecordError`, мягкий редирект |
| 6 | Сессия создавалась на каждый `/healthz`; нет очистки | `/healthz`,`/favicon.ico` исключены; purge протухших сессий |

### Остаётся на доработку (инфраструктура/процессы, вне кода)
Права файлов на хосте, сетевая изоляция app↔БД, управление Fernet-ключом (KMS/ротация),
шифрование метаданных, MFA/lockout, бэкапы, миграции и CI-сканеры. Подробности и
приоритеты — в `REPORT.md` (разделы 2–3, 6.4).
